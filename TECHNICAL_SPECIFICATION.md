# Техническое задание: MicrobeSim

## 1. Общие сведения

**Наименование:** MicrobeSim - Симулятор жизни микроорганизмов  
**Платформа:** Android 14+ (API 34)  
**Минимальная версия:** Android 7.0 (API 24)  
**Жанр:** Симулятор жизни / Эволюционный симулятор  
**Язык разработки:** Kotlin 1.9+

## 2. Анализ аналогов и исправление ошибок

### 2.1 Cell Lab - выявленные проблемы

| Проблема | Описание | Решение в MicrobeSim |
|----------|----------|---------------------|
| Производительность | Падение FPS при >500 клетках | Spatial Hashing, O(1) поиск соседей |
| Баланс | Быстрое вымирание или экспоненциальный рост | Адаптивный спавн питания, лимиты |
| Сложный UI | Неинтуитивный редактор генов | DSL + визуальный редактор |
| Нет сохранения | Прогресс теряется | Room Database для сохранений |
| Утечки памяти | При долгой игре | Object pooling, слабее ссылки |
| Мало контента | Ограниченные типы генов | 25+ типов генов |
| Нет туториала | Сложно начать | Интерактивное обучение |

### 2.2 Другие аналоги (Cell Planet, Evolution Simulator)

- **Cell Planet:** Красивая графика, но слабый геймплей → Делаем упор на глубину симуляции
- **Evolution Simulator:** Хорошая генетика, но нет визуала → Делаем качественную отрисовку

## 3. Функциональные требования

### 3.1 Система генома

**Гены должны включать:**
- Уникальный ID
- Тип поведения (enum)
- Параметры (Map<String, Float>)
- Условия активации (список Condition)
- Приоритет (Int 0-10)

**Типы генов (минимум 25):**
```
Движение: MOVE_RANDOM, MOVE_TOWARD_NUTRIENT, MOVE_AWAY_PREDATOR, 
          MOVE_TOWARD_LIGHT, MOVE_VERTICAL
          
Метаболизм: METABOLISM_FAST, METABOLISM_EFFICIENT, PHOTOSYNTHESIS,
            CHEMOSYNTHESIS, STORE_ENERGY
            
Размножение: DIVIDE_ASEXUAL, DIVIDE_SEXUAL, BUDDING

Защита: PRODUCE_TOXIN, FORM_SPORE, DEVELOP_ARMOR, CAMOUFLAGE

Социальное: SIGNAL_OTHERS, FORM_COLONY, COOPERATIVE_HUNT

Специализация: DIFFERENTIATE, SPECIALIZE_ATTACK, 
               SPECIALIZE_DEFENSE, SPECIALIZE_REPRODUCE
```

**Условия активации:**
- EnergyThreshold (мин/макс энергия)
- SizeThreshold (мин/макс размер)
- NutrientNearby (концентрация, радиус)
- PredatorNearby (дистанция)
- PopulationDensity (мин/макс плотность)
- TimeOfDay (часы)
- TemperatureRange (мин/макс температура)
- AlwaysActive (всегда активно)

### 3.2 Симуляция

**Требования к производительности:**
- Поддержка до 1000 клеток одновременно
- Стабильные 60 FPS на средних устройствах
- Время обновления < 16ms на тик

**Физика:**
- Движение с инерцией и трением
- Коллизии (опционально, для производительности можно отключить)
- Границы мира с отскоком

**Метаболизм:**
- Базовый расход энергии пропорционален размеру
- Разные типы метаболизма влияют на расход/эффективность
- Фотосинтез зависит от времени суток

**Размножение:**
- Бесполое: деление с мутацией генома
- Половое: конъюгация для обмена генами (опционально)
- Мутации: изменение параметров, добавление/удаление генов

### 3.3 Отрисовка

**Режимы качества:**
1. LOW: простые круги, без эффектов (для слабых устройств)
2. BALANCED: градиенты, мембраны
3. HIGH: тени, ядра, свечение

**Камера:**
- Панорамирование (drag)
- Зум (pinch-to-zoom): 0.1x - 5x
- Двойной тап для сброса
- Отслеживание выбранной клетки

**UI элементы:**
- Счётчик клеток (живые/всего)
- Счётчик питательных веществ
- Среднее поколение
- Время симуляции
- FPS counter
- Полоски энергии над клетками

### 3.4 Редактор генома

**Режимы создания:**
1. Визуальный: drag-and-drop генов
2. Текстовый: JSON редактор
3. DSL: упрощённый скриптовый язык

**Предустановленные шаблоны:**
- Basic Mover
- Nutrient Seeker
- Efficient Metabolism
- Fast Metabolism
- Asexual Reproducer
- Toxin Producer
- Photosynthesizer
- Colony Former
- Predator Avoider

### 3.5 Режимы игры

**Песочница:**
- Бесконечные ресурсы
- Нет целей
- Свободная эволюция

**Кампания:**
- Уровень 1: Выживание 60 секунд
- Уровень 2: Достичь 50 клеток
- Уровень 3: Эволюционировать хищника
- Уровень 4: Создать колонию
- Уровень 5: Доминирование вида

**Эксперимент:**
- Настройка параметров среды
- Добавление конкретных организмов
- Сбор статистики

## 4. Технические требования

### 4.1 Архитектура

**Паттерны:**
- ECS (Entity-Component-System) для гибкости
- Repository для данных
- Observer для событий симуляции
- Factory для создания организмов

**Структура пакетов:**
```
com.microbesim/
├── core/           # Константы, интерфейсы
├── genome/         # Гены, геномы, мутации
├── models/         # Cell, Nutrient, World
├── engine/         # SimulationEngine, SpatialHash
├── ui/             # Views, Activities, Compose
├── utils/          # ScriptEngine, Extensions
├── data/           # Repository, DAO (Room)
└── di/             # Dependency Injection (Hilt)
```

### 4.2 Оптимизация

**Spatial Hashing:**
- Размер ячейки: 100 единиц мира
- Хранение: Map<Long, MutableSet<SpatialObject>>
- Обновление: только при перемещении между ячейками

**Object Pooling:**
- Пул для частиц эффектов
- Пул для временных объектов (Vector2, Rect)
- Избегание аллокаций в update()

**Асинхронность:**
- Сохранение/загрузка в фоне (Coroutines)
- Парсинг JSON вне UI потока
- Предзагрузка ресурсов

### 4.3 Хранение данных

**Room Database:**
```kotlin
@Entity
data class SavedOrganism(
    @PrimaryKey val id: String,
    val name: String,
    val genomeJson: String,
    val createdAt: Long,
    val stats: String // JSON с статистикой
)

@Entity
data class GameProgress(
    @PrimaryKey val slotId: Int,
    val unlockedLevels: Int,
    val discoveredSpecies: List<String>,
    val totalTimePlayed: Long
)
```

**SharedPreferences:**
- Настройки графики
- Настройки звука
- Последняя сессия

### 4.4 Требования к коду

**Kotlin Best Practices:**
- Data classes для моделей
- Sealed classes для состояний
- Extension functions для утилит
- Coroutines Flow для реактивности

**Тестирование:**
- Unit тесты для Genome, Cell логики
- Integration тесты для SimulationEngine
- UI тесты для критических путей

**Документация:**
- KDoc для публичных API

- README с примерами использования

## 8. Риски и mitigation

| Риск | Вероятность | Impact | Mitigation |
|------|------------|--------|------------|
| Низкая производительность | Средняя | Высокий | Раннее профилирование, оптимизация hot paths |
| Сложный баланс | Высокая | Средний | Итеративная настройка, feedback тестеров |
| Scope creep | Высокая | Высокий | Строгое следование ТЗ, backlog для фич |
| Проблемы с памятью | Средняя | Высокий | Профилирование, leak detection |
